* Đọc cái này trước
Takuya (craftzdog) dùng Inkdrop như *nhật ký làm việc của dev*: mỗi project
một notebook, mỗi task/bug một note, vừa làm vừa ghi, xong thì đổi trạng thái.
Note không viết để đẹp mà để *nhớ hộ mình*: 6 tháng sau đọc lại vẫn hiểu
lúc đó đã làm gì, tại sao, và đã thử những gì.

File này là cách làm y như vậy với Emacs + Org + Denote, lưu trong repo
notes private trên GitHub.

- Phím ghi dạng meow (=SPC=). Không dùng meow: thay =SPC= bằng =C-c=
  (=SPC n d= → =C-c n d=, =SPC c t= → =C-c C-t=).
- Tập dần từng tuần: [[file:org-workflow.org][org-workflow.org]]. Mọi phím: [[file:keybindings.org][keybindings.org]].
- Bảng phím tóm tắt ở cuối file: [[*Bảng phím][Bảng phím]].

* 6 nguyên tắc
1. *Ghi lúc đang làm*, không đợi cuối ngày. Cuối ngày bạn chỉ nhớ kết quả,
   quên mất đường đi.
2. *Một cửa vào.* Nghĩ ra gì thì capture vào inbox, *không sắp xếp lúc ghi*.
   Sắp xếp là việc của cuối ngày.
3. *Ghi cả cái không work.* "Đã thử X, không được vì Y" là dòng có giá trị
   nhất khi gặp lại bug.
4. *Ghi lý do, không chỉ kết quả.* "Dùng =find_each=" thì vô dụng;
   "dùng =find_each= vì =all= load 2 triệu dòng, hết RAM" mới là note.
5. *Note ngắn, link nhiều.* Một note một ý. Liên quan thì link (=SPC n i=),
   đừng viết lại.
6. *Đóng vòng mỗi ngày:* inbox về 0, sync lên GitHub.

* Cài đặt một lần
** Repo notes = =~/org=
Config đọc note ở =~/org/=. Clone repo notes private của bạn vào đó
(đổi URL nếu tên repo khác):
#+begin_src sh
git clone git@github.com:hienhm2212/notes.git ~/org
cd ~/org
mkdir -p notes projects/archive
touch inbox.org tasks.org journal.org
#+end_src

Trong =tasks.org= tạo vài mục để refile vào:
#+begin_src org
,* Personal
,* Learning
#+end_src

Commit lần đầu rồi khởi động lại Emacs:
#+begin_src sh
git add -A && git commit -m "init notes" && git push
#+end_src
Làm y hệt trên cả MacBook và laptop công ty.

** Việc công ty để riêng
- =~/work-org/= trên laptop công ty, *không* phải git repo cá nhân,
  không bao giờ push lên GitHub của bạn.
- Tạo project công việc bằng =SPC n P= rồi trả lời =y= ("Work project?"):
  file nằm ở =~/work-org/projects/=.
- *Cẩn thận:* inbox (=SPC n c t=) và devlog (=SPC n c j=) nằm trong =~/org=,
  nên sẽ được push lên GitHub. Ở công ty, chi tiết công việc (tên khách hàng,
  log, số liệu, secret) ghi vào project công việc: =SPC n c p= (task),
  =SPC n c L= (log). Devlog chỉ ghi chung chung ("fix bug export CSV").

** Đồng bộ
- =SPC n g=: lưu mọi file Org, commit, =pull --rebase=, push. Bấm cuối ngày
  và trước khi chuyển máy.
- Bị conflict (sửa cùng chỗ trên 2 máy): mở một file trong =~/org=, =SPC v g=
  (Magit), sửa file bị conflict, stage (=s=), rồi tiếp tục rebase (=r r=).

* Ghi cái gì, vào đâu
| Bạn có...                             | Ghi vào                       | Phím               |
|---------------------------------------+-------------------------------+--------------------|
| Một việc cần làm (chưa biết của đâu)  | =inbox.org=                   | =SPC n c t=        |
| Việc của một project cụ thể           | =* Tasks= của project         | =SPC n c p=        |
| Link muốn đọc sau                     | =inbox.org= (copy link trước) | =SPC n c l=        |
| "Vừa làm xong X", "đang kẹt ở Y"      | =journal.org= (devlog)        | =SPC n c j=        |
| Kết quả họp, quyết định trong project | =* Log= của project           | =SPC n c L=        |
| Cuộc họp (người, quyết định, việc)    | =journal.org=                 | =SPC n c m=        |
| Một bug đang điều tra                 | Note Denote, từ khoá =bug=    | =SPC n c b=        |
| Kiến thức muốn giữ (TIL, how-to)      | Note Denote                   | =SPC n n=          |
| Quyết định lớn của project            | =* Decisions= của project     | mở project, gõ tay |

Phân biệt nhanh:
- =projects/= — hết giá trị khi project xong (task, log, quyết định).
- =notes/= — giữ mãi, dùng cho project sau (Go context, bug Rails, cách setup).
- =journal.org= — dòng thời gian: hôm nay đã làm gì.

* Một ngày
** Sáng — 5 phút
- [ ] =SPC n d=: lịch hôm nay, việc =NEXT=, việc =WAIT=, inbox còn sót.
- [ ] Chọn *tối đa 3* việc, chuyển sang =NEXT= (trong agenda: =t= rồi =n=).
- [ ] =SPC n c j=: một dòng devlog "Hôm nay: A, B, C".

** Bắt đầu một task
1. Chưa có thì tạo: =SPC n c p= → chọn project → =TODO Fix CSV export chậm=.
2. Đổi sang =NEXT= khi bắt đầu (=SPC c t= → =n=).
3. Task to (hơn nửa ngày)? Ghi ngắn dưới heading: mục tiêu, link ticket/PR.

** Trong lúc làm — phần "Takuya" nhất
Mỗi khi có điều đáng nhớ, ghi *1–2 dòng*, mất 10 giây:
- Tiến độ, ý tưởng, chỗ kẹt → devlog =SPC n c j=.
- Kết luận về project → log project =SPC n c L=.
- Gặp bug khó (quá 15 phút chưa ra) → mở note bug =SPC n c b= *ngay*
  khi đang đứng ở dòng code nghi ngờ: note tự có link về dòng đó.
- Đang code mà nghĩ ra việc khác → =SPC n c t=, ghi một dòng, quay lại làm
  tiếp. Không chuyển việc.

** Điều tra bug
Note bug có sẵn khung. Điền dần trong lúc làm, không đợi xong:
#+begin_src org
,* Symptom
Export CSV 10k đơn mất 8s (bình thường < 1s). Chỉ ở account lớn.
,* Reproduce
rails c → Exports::Csv.new(Account.find(42)).call
,* Tried
- Index orders.user_id → không đổi (vẫn 8s)
- Bật bullet → N+1 ở line_items ← đây rồi
,* Root cause
Mỗi order load line_items riêng: 10k query.
,* Fix
includes(:line_items) + find_each(batch_size: 1000). PR #123. 8s → 0.6s.
,* Links
[[file:~/work/shop/app/exports/csv.rb::42]]
#+end_src
- *Tried* là mục quan trọng nhất: ghi cả hướng sai và vì sao sai.
- Xong bug: liên kết từ project (=SPC n c L=: "Fix CSV chậm, xem note bug")
  và từ note bug sang note kiến thức nếu có (=SPC n i=).

** Họp
- =SPC n c m=: hỏi chủ đề, rồi điền People / Decisions / Action items.
- Mỗi action item của bạn → task (=SPC n c t= hoặc =SPC n c p=). Note họp
  chỉ là biên bản, việc phải nằm ở chỗ có agenda.

** Xong task
- =SPC c t= → =d= (DONE). Org tự thêm =CLOSED: [ngày giờ]=.
- Học được gì dùng lại được → note kiến thức (xem [[*Note kiến thức][Note kiến thức]]).

** Cuối ngày — 10 phút
- [ ] =SPC n o=: inbox về 0. Mỗi mục chọn một:
  refile (=SPC c w=), lên lịch (=SPC c s=), deadline (=SPC c d=), hoặc xoá.
- [ ] =SPC n c j=: 2–3 dòng devlog: xong gì, kẹt gì, mai làm gì trước.
- [ ] Việc dở dang: ghi bước tiếp theo vào ngay task đó
  ("Mai: chạy lại với batch 500").
- [ ] =SPC n g=: sync.

* Ghi như thế nào
** Devlog (journal)
Mỗi dòng có giờ sẵn. Viết như tin nhắn gửi chính mình:
#+begin_example
,* 09:10 Hôm nay: CSV export, review PR #120, đọc docs Turbo Streams
,* 11:40 CSV chậm do N+1 ở line_items, đang thử includes
,* 15:20 Xong CSV (8s → 0.6s). Kẹt: CI flaky ở spec payments, chưa rõ
,* 18:05 Mai: hỏi Nam về flaky spec trước, rồi PR #120
#+end_example
- Tốt: có số liệu, tên cụ thể, bước tiếp theo.
- Tránh: "làm việc", "fix bug", "họp" — đọc lại không biết gì.

** Log project
Kết luận và quyết định, không phải từng bước. Một mục một dòng:
#+begin_example
,* [2026-10-26 Mon 15:30] Chốt find_each thay all: all load 2M dòng, OOM trên worker
,* [2026-10-27 Tue 10:00] Khách đồng ý bỏ cột tax_code khỏi CSV
#+end_example
Quyết định lớn (đổi kiến trúc, chọn thư viện) chép thêm vào =* Decisions=
với 3 dòng: *Chọn gì*, *Vì sao*, *Đã cân nhắc gì khác*.

** Note kiến thức
- *Tiêu đề = câu trả lời hoặc câu hỏi*, đủ để tìm lại:
  - Tốt: "Rails find_each vs each khi bảng lớn", "Go context bị cancel khi nào".
  - Tránh: "Rails", "Ghi chú hôm nay", "Bug".
- *Từ khoá*: 1 loại + 1–2 chủ đề.
  - Loại: =bug idea learn research troubleshoot config perf ops project=
  - Chủ đề: =go ruby rails react js sql devops til=
  - Ví dụ: =perf rails=, =learn go=, =config devops=.
- *Nội dung*, chỉ những gì cần:
  #+begin_src org
,* Vấn đề / câu hỏi
,* Cách làm (code ngắn nhất chạy được)
,* Tại sao / lưu ý
,* Nguồn (link docs, PR, note liên quan)
  #+end_src
- TIL (học được trong ngày): note rất ngắn, từ khoá =til= + chủ đề.
  3 dòng là đủ.
- Sửa tiêu đề hoặc từ khoá sau: =SPC n r=.

** Khi nào tách note riêng
- Một ý đủ để tìm lại riêng → note riêng.
- Viết lần thứ hai cùng một thứ → tách ra note, chỗ khác chỉ link tới.
- Chỉ dùng trong project này → để trong project, không tạo note.

* Tuần — thứ Sáu, 20 phút
=SPC n w= mở checklist trong journal:
- [ ] Inbox về 0.
- [ ] Mỗi project =active= có 1–2 việc =NEXT=. Project không đụng tới
  tuần này → =SPC n S= → =hold=.
- [ ] Project xong → =SPC n S= → =done=, chuyển vào archive.
- [ ] Việc =WAIT=: cần nhắc ai?
- [ ] Đọc lại devlog tuần: thứ gì đáng thành note kiến thức thì tạo ngay.
- [ ] Viết 3 dòng: Went well / To improve / Focus next week.
- [ ] =SPC n g=.

* Tháng — 30 phút
- Lướt =~/org/notes/= trong Dired (=C-x d ~/org/notes=): note trùng ý thì gộp, tiêu đề
  mơ hồ thì sửa (=SPC n r=).
- Từ khoá mới hay dùng → thêm vào =denote-known-keywords= (=modules/my-org.el=).
- Note bug lặp lại nhiều lần → viết note "checklist" chung.

* Tìm lại
| Muốn tìm                      | Làm                                 |
|-------------------------------+-------------------------------------|
| Note theo tên                 | =SPC n f=, gõ vài chữ của tiêu đề   |
| Mọi note bug                  | =SPC n f=, gõ =_bug=                |
| Note theo hai từ khoá         | =SPC n f=, gõ =_perf _rails=        |
| Chữ bất kỳ trong mọi file Org | =SPC n s= (ripgrep)                 |
| Hôm đó đã làm gì              | =SPC n j= (journal), hoặc =SPC n s= |
| Task đã xong khi nào          | =SPC n s= tên task, xem =CLOSED:=   |
| Project cũ                    | =C-u SPC n p= (gồm cả archive)      |

* Lỗi hay gặp
- *Sắp xếp lúc capture.* Capture xong quay lại việc đang làm. Sắp xếp để
  cuối ngày.
- *Ghi bù cuối ngày.* Lúc đó chỉ còn kết quả, mất hết "đã thử gì".
- *Lên lịch mọi thứ.* Agenda đầy việc quá hạn → bỏ không xem nữa. Chỉ lên
  lịch việc có ngày thật.
- *Quá nhiều =NEXT=.* Mỗi project 1–2 cái. Còn lại để =TODO=.
- *Tiêu đề note mơ hồ.* Một tháng sau không tìm ra.
- *Quên sync.* Sang máy kia thấy thiếu note → =SPC n g= mỗi tối.
- *Chi tiết công việc lọt vào repo cá nhân.* Xem [[*Việc công ty để riêng][Việc công ty để riêng]].
